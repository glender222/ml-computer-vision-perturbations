## 4 Estrategia Dinámica de Reconocimiento Facial

En esta sección, explicamos primero por qué las estrategias de FR (estáticas) adoptadas en la literatura previa sobre AFR son insuficientes para caracterizar la capacidad de Trackers determinados (Sección 4.1). Esta observación nos motiva a desarrollar una dynamic FR strategy, DynTracker, que enriquece iterativamente la gallery database del modelo de FR del Tracker con las imágenes de Trackee recién identificadas (Sección 4.2). Además, mostramos resultados preliminares que demuestran que DynTracker puede reducir significativamente la eficacia de protección de los métodos de AFR existentes (Sección 4.3).

## 4.1 Motivación

Como se discutió en la Sección 3, una característica única del security game entre Tracker y Trackee es que las protecciones de AFR se despliegan en las imágenes de Trackee, las cuales luego se publican en línea antes de que Tracker inicie el rastreo. Dicho esto, las restricciones impuestas al modelar el comportamiento de Tracker deben ser lo menos restrictivas posible. De lo contrario, es probable que subestimemos la capacidad de los Trackers que están determinados a rastrear a Trackee. Desafortunadamente, los métodos de gallery-target y query-target AFR existentes asumen implícitamente en su evaluación que la gallery database de los modelos de FR utilizados por Tracker permanece fija. Denominamos a este entorno de evaluación como la static FR strategy. Por ejemplo, el gallery-target AFR inyecta pequeñas perturbaciones en las imágenes de galería de la identidad de Trackee y asume que $\tilde { \mathcal { D } } _ { \mathrm { g } }$ se utiliza como la gallery database, mientras que el query-target AFR utiliza un conjunto de datos de imágenes faciales limpias con identidades conocidas $\mathcal { D } _ { \mathrm { g } }$ como la gallery database. A pesar de las diferentes opciones, la gallery database permanecerá inalterada a lo largo de todo el proceso de rastreo.

Sostenemos que los Trackers determinados poseen tanto la capacidad como fuertes incentivos para actualizar la gallery database dinámicamente, en particular cuando el modelo de FR adoptado reconoce algunas de las imágenes de consulta de Trackee. En primer lugar, dado que muchos modelos de facial recognition bien entrenados están disponibles en línea, los Trackers pueden descargarlos fácilmente y realizar las modificaciones necesarias en la gallery database correspondiente para alcanzar su objetivo de rastreo. De hecho, la imagen facial inicial de Trackee debe insertarse en la gallery database para garantizar que el rastreo sea específico para el objetivo, lo cual ya justifica la capacidad del Tracker para actualizar la gallery database. En segundo lugar, los fuertes incentivos se deben al hecho de que podría existir abundante información sobre Trackee en las imágenes de consulta reconocidas como Trackee. Incluir estas imágenes identificadas de Trackee en la gallery database probablemente aumentará la exactitud del reconocimiento de la identidad objetivo, cumpliendo así con el objetivo de los Trackers determinados. Para respaldar nuestro argumento con evidencia más concreta, introduciremos DynTracker, una dynamic FR strategy que presenta un rastreo multironda y actualizaciones iterativas de la gallery database, y proporcionaremos resultados empíricos que muestran que DynTracker es mucho más potente que la static FR strategy para lograr el objetivo de rastreo en las siguientes secciones.

## 4.2 DynTracker: Dynamic FR Strategy

Hasta ahora, hemos explicado las limitaciones de las static FR strategies existentes utilizadas en la literatura de AFR y motivado la necesidad de considerar dynamic FR strategies para capturar mejor las capacidades e incentivos de Trackers determinados. En esta sección, presentamos el diseño detallado de nuestro DynTracker, el cual se ilustra en la Figura 2. Remitimos a los lectores al Algoritmo 1 en el apéndice de la versión completa de nuestro trabajo en ArXiv<sup>1</sup> para ver el pseudocódigo detallado de DynTracker. En particular, DynTracker consta de las siguientes etapas de rastreo:

**Preparación.** El Tracker posee inicialmente una única imagen de Trackee, ya sea limpia o protegida, y la incluye en la gallery database del modelo de FR. Se inicializa $\mathcal { D } _ { \mathbf { g } } ( 0 ) = \mathcal { D } _ { \mathbf { g } }$ como la gallery database al inicio del rastreo, y sea $\tilde { \mathcal { X } } _ { \mathrm { q } } ( 0 ) = \tilde { \mathcal { X } } _ { \mathrm { q } }$ el conjunto de imágenes de consulta recopiladas por Tracker, que consta tanto de imágenes protegidas por AFR de Trackee como de imágenes limpias de otras identidades. Aquí, utilizamos 0 para indicar la iteración 0 antes de que ocurra cualquier reconocimiento facial.

**Actualización Iterativa.** Como se discutió en la Sección 4.1, un Tracker determinado está incentivado a actualizar la gallery database del modelo de FR con las imágenes de consulta reconocidas y realizar un reconocimiento facial dinámico. Tomando la iteración $t$-ésima como ejemplo, Tracker obtiene primero $\mathcal{X} _ { \mathrm { ee } } ( t )$ , el conjunto de imágenes de consulta de Trackee predichas como $y _ { \mathrm { ee } }$ por el modelo de FR, luego incluye $\mathcal{X} _ { \mathrm { ee } } ( t )$ en la gallery database y realiza el $t$-ésimo reconocimiento facial. Para ser más específicos, la regla de actualización con respecto a la $t$-ésima iteración de DynTracker se define como: para cualquier $t = 1 , 2 , 3 , \ldots ,$

$$
\mathcal {X} _ {\mathrm{ee}} (t) = \left\{\boldsymbol {x} _ {\mathrm{q}} \in \tilde {\mathcal {X}} _ {\mathrm{q}} (t - 1) \mid \operatorname{FR} \left(\boldsymbol {x} _ {\mathrm{q}}; \mathcal {D} _ {\mathrm{g}} (t - 1)\right) = y _ {\mathrm{ee}} \right\},
$$

$$
\left. \mathcal {D} _ {\mathrm{g}} (t) = \mathcal {D} _ {\mathrm{g}} (t - 1) \cup \left\{\left(\boldsymbol {x}, y _ {\mathrm{ee}}\right) \mid \boldsymbol {x} \in \mathcal {X} _ {\mathrm{ee}} (t) \right\}, \right. \tag {6}
$$

$$
\tilde {\mathcal {X}} _ {\mathrm{q}} (t) = \tilde {\mathcal {X}} _ {\mathrm{q}} (t - 1) \setminus \mathcal {X} _ {\mathrm{ee}} (t),
$$

donde las imágenes identificadas de la iteración anterior se eliminan dinámicamente del conjunto de datos de consulta para evitar repeticiones, y escribimos explícitamente la dependencia de $\mathrm{FR}(\cdot)$ con respecto a la gallery database correspondiente para mayor claridad. Dado que $\mathcal { D } _ { \mathrm { g } } ( t )$ se actualiza dinámicamente, el conjunto de imágenes de consulta de Trackee $\mathcal{X} _ { \mathrm { ee } } ( t )$ devuelto por el modelo de FR será diferente para distintas iteraciones. Hablando técnicamente, podrían existir imágenes de otras identidades reconocidas incorrectamente como Trackee en el conjunto devuelto $\mathcal{X} _ { \mathrm { ee } } ( t )$ . Sin embargo, la false positive rate resulta ser muy baja si el modelo de FR está bien entrenado, lo cual ha sido verificado en nuestros experimentos (véase la Sección 7.3 para más discusiones sobre el impacto insignificante de las tasas de falsos positivos). Esta etapa de actualización iterativa inserta gradualmente más imágenes de Trackee en la gallery database para mejorar el reconocimiento de la identidad objetivo.

**Finalización.** Mientras se puedan reconocer nuevas imágenes de consulta con la identidad de Trackee $y _ { \mathrm { ee } } ,$ Tracker continuará la etapa de actualización iterativa, con el objetivo de descubrir tantas imágenes de Trackee como sea posible. Finalmente, Tracker completará todo el proceso de rastreo cuando no se devuelvan más imágenes de consulta de Trackee de la iteración anterior, ya que no se pueden obtener beneficios de un paso adicional de FR. Para facilitar la presentación, utilizamos $T$ para denotar el número total de iteraciones.

Aunque el conjunto de datos de la galería se actualiza dinámicamente durante el rastreo, el esquema de query matching sigue siendo el mismo, devolviendo aún la identidad de la imagen de la galería más similar a la imagen de consulta. A medida que se reconocen e incluyen más imágenes de Trackee en la gallery database, se espera que aumente la probabilidad de que las imágenes de consulta restantes de Trackee sean identificadas por el modelo de FR actualizado. Cabe señalar que la primera iteración de la fase de actualización dinámica corresponde a la static FR strategy utilizada en los métodos existentes de query-target AFR; por lo tanto, nuestro DynTracker es por diseño más potente en la identificación de las imágenes faciales de consulta de Trackee.

## 5 Promover la Diversidad para Combatir a DynTracker

Como se demostró en la Sección 4.3, los métodos de AFR existentes son razonablemente efectivos frente a la static FR strategy pero fallan frente a nuestro DynTracker. En esta sección, hipotetizamos que una razón fundamental tras dicho fracaso es la falta de diversidad en el diseño de las protecciones de AFR (Sección 5.1), lo que nos motiva aún más a desarrollar DivTrackee, un marco novedoso que promueve explícitamente la diversidad en la generación de protecciones de AFR para las imágenes de Trackee (Sección 5.2). Remitimos a los lectores al Algoritmo 2 en el apéndice de nuestro artículo completo para ver el pseudocódigo de DivTrackee.

## 5.1 Falta de Diversidad en los AFR Existentes

Antes de desarrollar contramedidas, es importante identificar la causa del fallo de los AFR existentes frente a DynTracker. Como se explicó en la Sección 4.2, la principal diferencia entre la static FR strategy y DynTracker radica en el conjunto de imágenes de galería correspondientes a la identidad de Trackee. A medida que DynTracker avanza con más actualizaciones iterativas, más imágenes de consulta reconocidas como Trackee se incluirán en la gallery database. En comparación con $\mathcal { D } _ { \mathrm { g } } ( 0 )$ , se espera que la gallery database actualizada después de la $t$-ésima iteración de DynTracker $\mathcal { D } _ { \mathrm { g } } ( t )$ contenga múltiples imágenes protegidas por AFR de Trackee, cubriendo así más variaciones de las características faciales de Trackee y pudiendo proporcionar información crucial sobre el esquema de protección de AFR desplegado, aspectos que incrementan las tasas de éxito de Tracker al rastrear a Trackee.

Hipotetizamos que las perturbaciones adversariales producidas por los AFR existentes comparten un patrón similar a través de diferentes imágenes faciales, causando el fracaso frente a dynamic FR strategies. Al revisar nuevamente la Tabla 1, podemos observar que las tasas de éxito de protección entre diferentes métodos de query-target AFR frente a la static FR strategy son consistentemente más bajas cuando Tracker comienza con una imagen protegida de Trackee, en comparación con las otras configuraciones limpias. Dicho rendimiento uniformemente reducido respalda nuestra hipótesis de que es probable que las perturbaciones adversariales generadas por un esquema de AFR específico compartan características similares, las cuales DynTracker puede explotar aún más. Para el generative-based AFR [19, 46, 51, 58], comúnmente se emplea una imagen facial auxiliar que pertenece a una persona diferente, denotada como $x _ { \mathrm { a u x } }$ para simplificar, para guiar el proceso de generación de imágenes objetivo. Sin embargo, la misma imagen auxiliar se comparte entre diferentes imágenes de consulta al generar perturbaciones de AFR, lo que potencialmente conduce a una baja efectividad de protección contra nuestro DynTracker. Para el AFR tradicional basado en ruido adversarial [13, 14, 32, 56], aunque no se utiliza ninguna imagen auxiliar $x _ { \mathrm { a u x } }$ , se basan en ejemplos adversariales no dirigidos (untargeted), los cuales pueden ser inherentemente propensos a ser clasificados erróneamente en una clase de identidad particular cercana a Trackee en el espacio latente. Creemos que el fallo de los métodos de AFR existentes en la protección de la privacidad frente a DynTracker puede atribuirse principalmente a la falta de promoción explícita de la diversidad en las generaciones de imágenes protegidas. ## 5.2 DivTrackee: AFR que Promueve la Diversidad

Basándonos en análisis anteriores, exploramos si promover la diversidad en AFR puede traducirse en una protección más efectiva. En las siguientes discusiones, nos centraremos en el generative-based AFR ya que puede preservar una mejor calidad visual de las imágenes faciales que el AFR basado en ruido adversarial. Además, a diferencia del gallery-target AFR que asume que los Trackers construirán la gallery database de su modelo de FR en un período de tiempo determinado [40], el generative-based AFR no impone suposiciones restrictivas sobre el comportamiento de Tracker para ser efectivo.

**Intento Inicial.** Nuestro primer intento consiste en promover la diversidad asignando a diferentes imágenes de Trackee distintas imágenes auxiliares en el generative-based AFR existente. Específicamente, sea $\mathcal{X} _ { \mathrm { a u x } }$ el conjunto de datos de imágenes auxiliares con identidades distintas. Para cualquier imagen limpia de Trackee $\boldsymbol{x}_{\mathrm{ee}}$, uno puede seleccionar aleatoriamente una imagen auxiliar $x _ { \mathrm { a u x } } \in \mathcal { X } _ { \mathrm { a u x } } ,$ y luego aplicar algún método de generative-based AFR para generar la protección en $x _ { \mathrm { e e } } .$ Dado que se utilizan imágenes auxiliares seleccionadas aleatoriamente con identidades diferentes para guiar el proceso de generación de imágenes, se espera que aumente la diversidad de las imágenes protegidas de Trackee.

Bajo la misma configuración de nuestros experimentos preliminares en la Sección 4.3, evaluamos si diversificar las imágenes auxiliares puede ayudar a mejorar el rendimiento de AFR. Seleccionamos 2000 imágenes de distintas identidades de LFW [20] para construir el conjunto de datos auxiliar $\mathcal{X} _ { \mathrm { a u x } } .$ La Tabla 2 muestra los resultados de la evaluación para algunos métodos de AFR basados en maquillaje con imágenes auxiliares diversificadas. En comparación con la fijación de la imagen auxiliar, diversificar las imágenes auxiliares aumenta el éxito de protección de generative-based AFR contra DynTracker. En particular, las tasas de éxito de rastreo de DynTracker frente a Clip2Protect se reducen en un 15.39% y un 12.23%, respectivamente, cuando Tracker posee inicialmente una única imagen de Trackee limpia y protegida. Para DiffAM, diversificar las imágenes auxiliares mejora el rendimiento en casi un 20% frente a DynTracker. No obstante, la mejora general limitada en la efectividad de la protección resulta insatisfactoria desde la perspectiva de Trackee. Por lo tanto, damos un paso más para explorar el concepto de diversidad y proponemos DivTrackee, un nuevo método de generative-based AFR con módulos y pérdidas promotores de la diversidad para mejorar la eficacia de protección de las imágenes de Trackee contra DynTracker.

**Generación de AFR Guiada por Texto (Text-Guided AFR Generation).** Adoptamos StyleGAN [23], que se ha empleado para diversas tareas de generación y edición de imágenes guiadas por texto [42, 44, 46, 52, 59], como la red troncal generativa (generative backbone) de DivTrackee. Sea $G _ { \theta } : \mathcal { W } \to \mathcal { X }$ un modelo generativo que mapea un vector latente $\boldsymbol{w} \in \mathcal { W }$ a una imagen facial generada $G _ { \theta } ( \boldsymbol { w } )$ . Dada una imagen limpia de Trackee $x _ { \mathrm { e e } }$ y un prompt de texto objetivo $p _ { \mathrm { t a r g } } ~ ( \mathrm { p . ~ ej . , }$ "natural makeup"), el objetivo es buscar un código latente $\hat{\boldsymbol{w}} \in \mathcal { W }$ tal que la imagen generada $G _ { \theta } ( \hat { \pmb w } )$ siga las especificaciones del prompt de texto $p _ { \mathrm { t a r g } }$ y satisfaga las expectativas para AFR de Trackee discutidas en la Sección 3. El uso de modelos generativos text-guided y prompts de maquillaje permite facilidad y flexibilidad en la creación de perturbaciones de AFR naturales en las imágenes faciales de Trackee.

Para obtener un $\hat{\boldsymbol{w}}$ deseable, comenzamos encontrando una buena inicialización $w _ { \mathrm { i n i t } }$ tal que $G _ { \theta } ( \pmb { w } _ { \mathrm { i n i t } } )$ esté cerca de $x _ { \mathrm { e e } }$ para asegurar la similitud visual. Aprovechando la técnica basada en inversión para la manipulación de imágenes de StyleGAN [52], utilizamos un encoder e4e preentrenado $F _ { \phi } : \mathcal { X } \to \mathcal { W }$ para inferir la inversa de la imagen limpia de Trackee como la inicialización $\pmb { w } _ { \mathrm { i n i t } } = F _ { \phi } ( \pmb { x } _ { \mathrm { e e } } )$ . Inspirándonos en [43, 46], realizamos fine-tuning del generador $G _ { \theta }$ para mejorar la calidad de la imagen reconstruida $G _ { \theta } \big ( F _ { \phi } ( \boldsymbol { x } _ { \mathrm { e e } } ) \big )$ sin sacrificar las capacidades de edición del modelo generativo (véase el apéndice de nuestro artículo completo para los detalles de implementación de este paso de fine-tuning del generador). Después de adquirir el generador ajustado, denotado como $G _ { \theta ^ { * } }$ , aplicamos gradient descent sobre una loss function cuidadosamente diseñada $\mathcal { L } _ { \mathrm { t o t } }$ para optimizar $\mathbf { w } _ { \mathrm { i n i t } }$ . Para ser más específicos, la regla de actualización por gradiente se define como: para cualquier $s = 0 , 1 , 2 , \ldots , S - 1$

$$
\boldsymbol {w} _ {s + 1} = \boldsymbol {w} _ {s} - \lambda \nabla_ {\boldsymbol {w}} \mathcal {L} _ {\text {tot}} (\boldsymbol {w} _ {s}). \tag {7}
$$

Aquí $\pmb { w } _ { 0 }$ se inicializa como $w _ { \mathrm { i n i t } }$ , $S$ es el número total de actualizaciones de gradiente y $\lambda$ denota el tamaño del paso (step size). En particular, $\mathcal { L } _ { \mathrm { t o t } }$ representa la total loss function que codifica todas las expectativas de Trackee para la generación de AFR guiada por texto, la cual se detallará a continuación.

**Pérdida Adversarial Promotora de la Diversidad (Diversity-Promoting Adversarial Loss).** Ahora que hemos determinado el framework generativo, la tarea restante es diseñar la pérdida total $\mathcal { L } _ { \mathrm { t o t } }$ tal que la salida final de la optimización basada en gradiente $G _ { \theta ^ { * } } ( \boldsymbol { w } _ { S } )$ logre altas tasas de éxito de protección contra DynTracker y mantenga la calidad visual con referencia a la imagen original de Trackee $x _ { \mathrm { e e } }$ y al prompt de texto dado $p .$ Para lograr una alta protection efficacy contra DynTracker, diseñamos la siguiente adversarial loss que promueve explícitamente la diversidad:

$$
\mathcal {L} _ {\text {eff}} (\boldsymbol {w}) = \mathcal {L} _ {\text {adv}} (\boldsymbol {w}) + \alpha_ {1} \cdot \mathcal {L} _ {\text {guide}} (\boldsymbol {w}) + \alpha_ {2} \cdot \mathcal {L} _ {\text {div}} (\boldsymbol {w}), \tag {8}
$$

donde $\alpha _ { 1 } \geq 0$ y $\alpha _ { 2 } \geq 0$ son hiperparámetros que controlan los pesos de cada término de pérdida. En particular, $\mathcal { L } _ { \mathrm { e f f } }$ consta de tres términos: una adversarial loss $\mathcal { L } _ { \mathrm { a d v } } ,$ una diverse guidance loss $\mathcal { L } _ { \mathrm { g u i d e } }$ y una diversity-promoting loss ${ \mathcal { L } } _ { \mathrm { d i v } } ,$ que se detallan a continuación:

Pérdida Adversarial (Adversarial Loss). El primer término de pérdida $\mathcal { L } _ { \mathrm { a d v } }$ en la Ecuación 8 contribuye al objetivo principal de dodging: evitar que $G _ { \theta ^ { * } } ( w )$ sea reconocido con la identidad de Trackee. Específicamente, sea $f$ un facial feature extractor; entonces la adversarial loss $\mathcal { L } _ { \mathrm { a d v } }$ se define como:

$$
\mathcal {L} _ {\mathrm{adv}} (\boldsymbol {w}) = - \mathrm{D} _ {f} \left(G _ {\theta^ {*}} (\boldsymbol {w}), \boldsymbol {x} _ {\mathrm{ee}}\right), \tag {9}
$$

donde $\mathrm { D } _ { f } : \mathcal{X} \times \mathcal{X} \to [ 0 , 2 ]$ captura la disimilitud coseno entre las características de dos imágenes de entrada extraídas por el feature extractor $f , \mathrm { es~decir, } ~ \mathrm { D } _ { f } ( \boldsymbol { x } _ { 1 } , \boldsymbol { x } _ { 2 } ) = 1 - \cos \left( f ( \boldsymbol { x } _ { 1 } ) , f ( \boldsymbol { x } _ { 2 } ) \right)$ . Nótese que el feature extractor utilizado en $\mathcal { L } _ { \mathrm { a d v } }$ no necesita ser el mismo que el de DynTracker. A medida que optimizamos $\boldsymbol{w}$ para reducir $\mathcal { L } _ { \mathrm { a d v } }$ mediante gradient descent, se espera que $G _ { \theta ^ { * } } ( w )$ sea menos similar a la imagen original de Trackee $x _ { \mathrm { e e } }$ en el espacio latente de características faciales.

Pérdida de Guía Diversa (Diverse Guidance Loss). El segundo término $\mathcal { L } _ { \mathrm { g u i d e } }$ en la Ecuación 8 denota la diverse guidance loss, la cual alienta a que la imagen generada $G _ { \theta ^ { * } } ( w )$ se acerque a una imagen auxiliar seleccionada aleatoriamente $x _ { \mathrm { a u x } }$ hasta cierto umbral basado en margen $\delta \geq 0$ . Específicamente, la diverse guidance loss $\mathcal { L } _ { \mathrm { g u i d e } }$ se define como:

$$
\mathcal {L} _ {\text {guide}} (\boldsymbol {w}) = \max \left(0, \mathrm{D} _ {f} \left(G _ {\theta^ {*}} (\boldsymbol {w}), \boldsymbol {x} _ {\text {aux}}\right) - \delta\right). \tag {10}
$$

De manera similar a nuestro intento inicial, a cada imagen diferente de Trackee $x _ { \mathrm { e e } }$ se le asignará una imagen auxiliar aleatoria $x _ { \mathrm { a u x } }$ seleccionada de un conjunto de datos $\mathcal{X} _ { \mathrm { a u x } }$ para guiar la generación. Empleamos además una pérdida basada en margen con un umbral $\delta$ para permitir direcciones menos restrictivas para buscar el código latente deseable.

Pérdida Promotora de la Diversidad (Diversity-Promoting Loss). El último término de pérdida $\mathcal { L } _ { \mathrm { d i v } }$ en la Ecuación 8 promueve explícitamente la diversidad dentro de las imágenes protegidas generadas de Trackee. Específicamente, se mantiene una cola $Q$ con una longitud máxima $m > 0$ utilizando el principio de primero en entrar, primero en salir (FIFO). Para cualquier imagen de consulta recién llegada de Trackee $x _ { \mathrm { e e } } , \mathcal { L } _ { \mathrm { d i v } }$ se define como la disimilitud coseno promedio respecto a las imágenes almacenadas previamente en $Q$:

$$
\mathcal {L} _ {\mathrm{div}} (\boldsymbol {w}) = - \frac {1}{m} \sum_ {\boldsymbol {x} \in Q} \mathrm{D} _ {f} \left(G _ {\theta^ {*}} (\boldsymbol {w}), \boldsymbol {x}\right). \tag {11}
$$

Nótese que $Q$ se expande secuencialmente a medida que generamos las imágenes protegidas de Trackee. Cuando llega la primera imagen de Trackee, $Q$ está vacía, por lo que inicialmente $\mathcal { L } _ { \mathrm { d i v } } = 0$ . Después de que se genera y almacena la primera imagen protegida en $Q ,$ la generación de la nueva imagen debe tomar en cuenta las anteriores. Cuando $|Q|$ alcanza la longitud máxima permitida $m$, la cola $Q$ se actualizará de manera FIFO. En nuestros experimentos, configuramos $m = 10$ para lograr el objetivo de promover la diversidad sin incurrir en una alta sobrecarga computacional, donde aumentar más el valor de $m$ no mejora mucho el rendimiento. Minimizar $\mathcal { L } _ { \mathrm { d i v } }$ incentiva a que la imagen recién generada $G _ { \theta ^ { * } } ( w )$ sea disímil a las imágenes protegidas de Trackee previamente almacenadas, promoviendo así la diversidad en AFR y mejorando la protección contra DynTracker. Como se ilustrará en la Sección 7.2, los términos de pérdida promotores de diversidad propuestos, $\mathcal { L } _ { \mathrm { g u i d e } }$ y $\mathcal { L } _ { \mathrm { d i v } } ,$ son esenciales para que DivTrackee logre altas tasas de éxito de protección.

**Diseño de Pérdida para la Calidad Visual (Loss Design for Visual Quality).** Además de diseñar la pérdida adversarial promotora de diversidad necesaria para lograr una protección efectiva frente a DynTracker, también debemos garantizar la calidad visual de las imágenes generadas. Para lograr este objetivo, adoptamos la siguiente pérdida inspirada en trabajos previos [15, 28, 46]:

$$
\mathcal {L} _ {\text {vis}} (\boldsymbol {w}) = \alpha_ {3} \cdot \mathcal {L} _ {\text {align}} (\boldsymbol {w}) + \alpha_ {4} \cdot \mathcal {L} _ {\text {latent}} (\boldsymbol {w}), \tag {12}
$$

donde $\alpha _ { 3 } \geq 0$ y $\alpha _ { 4 } \geq 0$ son hiperparámetros que controlan el trade-off. En particular, el primer término $\mathcal { L } _ { \mathrm { a l i g n } }$ en la Ecuación 12 captura la alineación de los embeddings con respecto a los pares texto-imagen entre la imagen inicial y la generada, basándose en un modelo CLIP preentrenado [39]. Sean $E _ { \mathrm { I } }$ y $E _ { \mathrm { T } }$ los codificadores preentrenados de imagen y texto de CLIP, respectivamente; entonces $\mathcal { L } _ { \mathrm { a l i g n } }$ se define como:

$$
\mathcal {L} _ {\text {align}} (\boldsymbol {w}) = 1 - \cos (\Delta I, \Delta T), \tag {13}
$$

donde $\Delta I = E _ { \mathrm { I } } \big ( G _ { \theta ^ { * } } ( \pmb { w } ) \big ) - E _ { \mathrm { I } } \big ( G _ { \theta ^ { * } } ( \pmb { w } _ { \mathrm { i n i t } } ) \big )$ es la distancia entre los embeddings de imagen, $\Delta T = E _ { \mathrm { T } } ( p _ { \mathrm { t a r g } } ) - E _ { \mathrm { T } } ( p _ { \mathrm { s r c } } )$ denota la distancia entre los embeddings de texto, y $p _ { \mathrm { s r c } }$ es el prompt de texto semántico de la imagen de consulta $x _ { \mathrm { e e } } .$ Siguiendo a [46], simplemente establecemos $p _ { \mathrm { s r c } }$ como $\text{"}face\text{"}$ dado que generalmente trabajamos con imágenes faciales. Dicha pérdida de alineación favorece que las imágenes generadas sigan más de cerca las especificaciones del prompt de texto objetivo. Finalmente, el último término $\mathcal { L } _ { \mathrm { l a t e n t } }$ en la Ecuación 12 penaliza la distancia euclidiana entre el código latente actual $\boldsymbol{w}$ y el código latente inicial $w _ { \mathrm { i n i t } } \mathrm { : }$

$$
\mathcal {L} _ {\text {latent}} (\boldsymbol {w}) = \| \boldsymbol {w} - \boldsymbol {w} _ {\text {init}} \| _ {2}. \tag {14}
$$

Al mantener $\boldsymbol{w}$ cerca de $w _ { \mathrm { i n i t } } , \mathcal { L } _ { \mathrm { l a t e n t } }$ asegura la similitud visual entre las imágenes iniciales y las generadas. Uniendo todas las partes, diseñamos la total loss function como $\mathcal { L } _ { \mathrm { t o t } } ( \pmb { w } ) = \mathcal { L } _ { \mathrm { e f f } } ( \pmb { w } ) + \mathcal { L } _ { \mathrm { v i s } } ( \pmb { w } )$ y realizamos gradient descent sobre $\mathcal { L } _ { \mathrm { t o t } }$ para obtener el código latente optimizado $\boldsymbol { w } _ { S }$ con base en la Ecuación 7. Finalmente, $G _ { \theta ^ { * } } ( w _ { S } )$ se devolverá como la imagen protegida de Trackee correspondiente a la original $x _ { \mathrm { e e } } .$
